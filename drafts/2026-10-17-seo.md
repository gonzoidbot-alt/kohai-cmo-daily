### Fix 2 — MEDIUM severity: sitemap-0.xml carries zero `<lastmod>` on all 52 URLs, stacking with a 9-week blog freeze

**Verified:** `sitemap-0.xml` today contains 52 `<url>` entries and **0 `<lastmod>` elements**. Meanwhile the blog listing's newest dated post is August 11, 2026 — so both freshness signals a crawler can read (sitemap lastmod, on-page recency) are silent, and Google has no way to tell that pricing pages changed (the ladder visibly changed since the docs were written) or that comparison pages were added. This also devalues the site's own change history: 10-12→10-16 crawls show the site ships fixes continuously, none of it signalable.

**Copy-paste (per-URL addition in the sitemap template):**

```xml
<url>
  <loc>https://kohai.co/pricing</loc>
  <lastmod>2026-10-17</lastmod>
</url>
```

Emit `<lastmod>` from each page's actual build/git-modified date — never a hardcoded "today", since fake lastmods get ignored after the first trust violation. If the pipeline can't source real dates, prefer omitting lastmod over fabricating it (Google's guidance), and fix the source.

**Same batch, one line each:** (a) trailing-slash variants 307-redirect (`/pricing/` → `/pricing`, `/vs/` → `/vs`) — 307 is a *temporary* redirect class; these are permanent canonicalizations and should be 301/308; (b) every page ships the same `og:image` default (`/images/og/default.jpg`, incl. `/vs/lindy`) — per-page OG images are low-effort conversion for social/SERP sharing of comparison pages.

**Why it ranks second:** it's infrastructure, not copy — no sign-off loop — but its impact is indirect (crawl efficiency + freshness trust), so it sits below Fix 1's direct query coverage.

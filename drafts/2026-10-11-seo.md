## Fix 2 — Add FAQPage schema to /pricing and the /vs/ pages (severity: HIGH — the FAQ markup that matches FAQ content that already exists)

**Finding:** Every page checked serves identical JSON-LD: `Organization` + `WebSite` only. There is **no FAQPage, Product/Offer, or BlogPosting schema anywhere** — verified on `/pricing`, `/vs/lindy`, and blog article pages.

Why it's the #2 priority: the FAQ content already exists on-page (pricing FAQ, each /vs/ "answered" section) — the structured data is the missing layer, not new copy. FAQPage markup is what makes these Q&As quotable by AI engines (06 § Stage 2: "structure pages for lifting") and eligible for rich results in Google. This is a template-level fix across two templates, not a per-page effort.

**Fix — append to the JSON-LD array on the /pricing template:**

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "How much does Kohai cost?",
      "acceptedAnswer": { "@type": "Answer", "text": "Kohai is free to start with no card needed. Paid plans are $20/month (8,000 credits), $100/month Kohai Pro (40,000 credits), and $200/month Kohai Max (80,000 credits). Every plan includes unlimited team seats and the whole team of AI teammates." }
    },
    {
      "@type": "Question",
      "name": "Do I need to build agents or write prompts?",
      "acceptedAnswer": { "@type": "Answer", "text": "No. You brief Kohai the way you'd brief a colleague — one message describing the outcome is enough. A Chief of Staff splits the goal into tasks and hands each to the right teammate with the right tools already connected." }
    },
    {
      "@type": "Question",
      "name": "Is my data used to train AI models?",
      "acceptedAnswer": { "@type": "Answer", "text": "No. Kohai runs exclusively on open-weight models (DeepSeek, Kimi, GLM) via inference providers that do not train on your data, with per-tenant isolation and encryption." }
    }
  ]
}
```

**And on each /vs/ template, generate the same shape from that page's existing Q&A content**, e.g. for /vs/lindy:

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "Kohai vs Lindy — which should you choose?",
      "acceptedAnswer": { "@type": "Answer", "text": "Choose Kohai if you want a ready-made team of AI teammates that hands back finished work. Choose Lindy if you want to build your own assistant and workflows yourself." }
    }
  ]
}
```

(Pull each page's actual answer text from its existing "answered" section — don't paraphrase a second version of the truth; the schema should mirror the on-page copy exactly.)

**Bonus while in the templates:** the homepage `<title>` is "Kōhai | Onboard AI teammates. Get work finished." — brand-first, zero money keywords. A candidate rewrite: "Kōhai — Onboard AI teammates and get work finished | AI workforce for small business". Lower urgency than the two fixes above since brand queries already resolve, but free to ship in the same PR.

## Keyword-gap observation — the money pages don't exist yet

04 § SEO/GEO targets lists four money-page queries: **"AI employees for small business", "AI workforce platform", "hire AI employees", "Lindy alternative" / "Artisan alternative"**. Crawling the 104-URL sitemap:

- **"Lindy alternative" / "Artisan alternative"**: covered indirectly by /vs/lindy and /vs/artisan (comparison intent, close enough) — but there is no page targeting the "alternative" phrasing itself, which is the exact query Lindy's SEO content siphons ("Sintra AI Pricing" on lindy.ai/blog, per 01).
- **"AI employees for small business"**: partially covered by blog posts, but note the term mismatch — the blog writes "AI **teammate**" (brand glossary) where search demand says "AI **employee**". `/blog/what-is-an-ai-employee` is titled "What is an AI teammate?" — the slug targets one head term and the title/H1 targets another, splitting the page's relevance. Keep "teammates" in product copy per the design guide, but let titles/H2s on top-of-funnel pages carry the term buyers actually search.
- **"AI workforce platform" and "hire AI employees"**: no page targets these at all.
- **The planned `/ai-colleagues` GEO anchor page (04 § launch week D3: "GEO anchor page: /ai-colleagues explainer") is still a 404** — it never shipped. That single page was meant to be the citable definitional anchor for the "AI colleagues" category phrase across all four money terms.

**Recommendation:** the highest-leverage single addition is shipping the /ai-colleagues explainer as a real money page (H2s as questions per 06 § Stage 2, FAQPage schema from Fix 2, sitemap entry), positioned around "AI colleagues / AI workforce platform" with the /vs/ and blog pages linked as supporting depth. Second: one "X alternatives" cluster (lindy-alternative, artisan-alternative pages or H2 sections on the existing /vs/ pages) to contest the query space Lindy is already farming.

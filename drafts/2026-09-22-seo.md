## SEO Fix #1 — Severity: CRITICAL (new) — Cloudflare is serving HTTP 403 to GPTBot, ClaudeBot, and CCBot sitewide

**Finding.** robots.txt is permissive, but the edge is not. Verified today with a user-agent matrix against `/`, `/pricing`, `/technology`, `/blog`:

| User agent | Result |
|---|---|
| plain curl / browser UA / **Googlebot** | 200 on all pages |
| **OAI-SearchBot**, **ChatGPT-User**, **PerplexityBot**, **Google-Extended** | 200 — allowed |
| **GPTBot** | **403** on every page ("Your request was blocked.", 25-byte body) |
| **ClaudeBot** | **403** on every page |
| **CCBot** | **403** on every page |
| /robots.txt | 200 for all agents (they can read the rules; they just can't read the site) |

Server header: `server: cloudflare`, so this is a Cloudflare-layer block, not an app rule. The selective pattern (GPTBot/ClaudeBot/CCBot blocked; OAI-SearchBot, PerplexityBot, ChatGPT-User, Google-Extended allowed) matches Cloudflare's managed **"Block AI Scrapers and Crawlers"** bot rule — it is almost certainly one toggle in the dashboard, not something anyone decided page-by-page.

**Why this outranks everything else.** 06 Stage 1–2 makes AI-engine readability Stage 1–2 work (51% of B2B buyers start research with an AI chatbot). robots.txt allowing GPTBot while the WAF 403s it means: ChatGPT browsing, Claude, and Common Crawl (which feeds many model training/grounding sets) can never see kohai.co content — the /vs/ pages, pricing, and blog are invisible to exactly the engines the GEO checklist targets. Yesterday's draft marked "robots.txt allows AI crawlers ✅" — that check passed robots.txt's front door while the building's door was locked. 09-14's CRITICAL issue is therefore only **half-fixed**: the polite-crawler layer was opened; the network layer is still closed.

**Fix (no code — a settings change + a verification habit).**

1. Cloudflare dashboard → the kohai.co zone → **Security → Bots** → find **"AI Scrapers and Crawlers"** (currently Block) → set to **Allow** (or delete the rule if it's a custom WAF rule).
2. If it's a WAF custom rule instead: Security → WAF → Custom rules — find any rule with an expression like `(cf.client.bot)` or `http.user_agent contains "GPTBot"` with action Block/Managed Challenge, and either delete it or add a Skip rule above it:

```
# WAF custom rule — let AI crawlers through (per 04/06: GEO is a launch goal)
(http.user_agent contains "GPTBot")
or (http.user_agent contains "ClaudeBot")
or (http.user_agent contains "CCBot")
→ Action: Skip · uncheck all remaining protections for this rule
```

3. Keep OAI-SearchBot/PerplexityBot behavior as-is (already allowed — correct, since those are citation surfaces).
4. **Verify after the change** (should print 200 for each):

```
curl -s -o /dev/null -w "GPTBot %{http_code}\n"      -A "GPTBot/1.0 (+https://openai.com/gptbot)" https://kohai.co/
curl -s -o /dev/null -w "ClaudeBot %{http_code}\n"   -A "Mozilla/5.0 (compatible; ClaudeBot/1.0; +claudebot@anthropic.com)" https://kohai.co/
curl -s -o /dev/null -w "CCBot %{http_code}\n"       -A "CCBot/2.0 (https://commoncrawl.org/faq/)" https://kohai.co/
```

**Effort:** ~10 minutes in the Cloudflare dashboard. **Priority rationale:** every other item on this list and on yesterday's list is worthless to ChatGPT/Claude while this 403 stands — it is the new top of the 06 Stage-1 checklist.

## SEO Fix #2 — Severity: HIGH (new) — The "AI colleagues" category phrase is disappearing from the crawlable site: homepage title/meta drifted to "AI teammates", and /technology's meta describes a page that no longer exists

**Finding (two related regressions, both verified in raw HTML today).**

1. **Homepage drift.** Title is now `Kōhai — Onboard AI teammates. Get work finished.` and the meta description is *"Kōhai puts a collaborative AI workspace inside every business — deploying autonomous AI teammates across any function."* On the 09-21 crawl both read "Onboard AI colleagues." Body-copy counts on `/` today: "teammate" ×18, "colleague" ×3, "AI employee" ×0, "AI workforce" ×0. Two problems:
   - 04/06 name **"AI colleagues, not agents"** as category phrase #1, and the north-star metric is phrase association for it. The one page every engine and human sees first has quietly switched vocabulary.
   - "deploying **autonomous** AI teammates" cuts against the positioning: 02's voice rules say approval-gate humility — "never sell full autonomy as the dream." "Autonomous" is also the exact word the /vs/ pages position *against* (vs/lindy's own meta: "build your own assistant vs. a ready-made team").
2. **/technology stale meta.** Title "Technology — Kōhai" is fine, but the meta description is *"Your developers spend half their time on non-coding tasks. AI handles code review, documentation, incidents, and onboarding…"* while the page's H1/H2s are now "Ship faster without bloating your headcount / What your Kohai team does / The team on this goal" — a dev-team solutions page. The description looks lifted from an old article, mismatches the page, and (see keyword gap below) the page itself no longer mentions DeepSeek, Kimi, GLM, or open-weight even once.

**Fix (copy-paste, homepage `<head>`; keeps the verified pricing anchor and restores the category phrase):**

```html
<title>Kōhai — Hire AI colleagues. Get work finished.</title>
<meta name="description" content="Hire AI colleagues instead of building agents. Describe the outcome — a team assembles, works in your ~1,000 tools, and delivers finished work to your Library. Sensitive actions wait at an approval gate. Open-weight models only. 7-day free trial.">
```

And for `/technology` (description matching the live page):

```html
<title>Technology — Kōhai</title>
<meta name="description" content="Give every function a Kohai team: engineering, ops, sales, support. Brief the goal — your AI teammates plan the work, use your tools, and ship finished work. Sensitive actions wait at an approval gate.">
```

In Astro this is the site-wide `<title>`/description defaults in the base layout plus the one frontmatter override for `/technology` — a 15-minute change. Recommended policy so it doesn't drift again: the strings "AI colleague(s)" and "approval gate" should appear in the title-or-description of every money page (home, pricing, features, technology, all /vs/), enforced the same way the quotable-claim rule is enforced on content.

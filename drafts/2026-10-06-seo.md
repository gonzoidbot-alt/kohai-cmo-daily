## Fix 1 — (Severity: HIGH, carried 4th day, verified regressed again today) Sitemap has zero `lastmod` on all 52 URLs — and there's now proof the staleness is costing index freshness

**What:** `sitemap-0.xml` emits bare `<url><loc>…</loc></url>` with no `<lastmod>` on any of the 52 URLs. This was recorded as fixed on 10-02, regressed by 10-03, and has stayed regressed through 10-06. Today it stopped being theoretical: a third-party SERP snapshot of `kohai.co/` captured today still shows the **pre-rename homepage copy** ("Onboard AI **colleagues**…" while the live page says "Onboard AI **teammates**…") — Google's index is serving weeks-old copy for the brand's own homepage, and with no lastmod (and titles unshipped, llms.txt unshipped) nothing is telling crawlers the site changed. Every other fix on the board (titles, schema, llms.txt, /vs pricing tweaks) depends on prompt re-crawling to pay off.

**Where:** sitemap generation (Astro integration config — the site is Astro per the `data-astro-cid-*` attributes).

**Copy-paste** (Astro `@astrojs/sitemap` supports this natively via a `serialize` hook in `astro.config.mjs` — use file mtimes so it can't regress silently):

```js
// astro.config.mjs
import { statSync } from 'node:fs';
import { fileURLToPath } from 'node:url';

export default defineConfig({
  sitemap: {
    serialize(item) {
      // map each URL to its built file on disk and stamp real mtime
      const path = item.url === 'https://kohai.co/'
        ? 'dist/index.html'
        : 'dist' + new URL(item.url).pathname.replace(/\/$/, '') + '/index.html';
      try { item.lastmod = statSync(path).mtime.toISOString(); } catch { /* leave off */ }
      return item;
    },
  },
});
```

If the build is static-from-CMS rather than file-mtime-based, stamp from the page's own "Last reviewed" date instead (the /vs pages already display one, e.g. vs/lindy: "Last reviewed June 16, 2026" — it's in the DOM, so pipe it into the sitemap).

**Verify after shipping:**

```bash
curl -s https://kohai.co/sitemap-0.xml | grep -c lastmod   # expect 52
```

## Fix 2 — (Severity: MEDIUM-HIGH, next-priority schema item not covered by the 10-04 draft) 20 blog posts ship with no `Article`/`BlogPosting` JSON-LD — dates visible in the UI but invisible to machines

**What:** The 10-04 draft's Fix 1 covered FAQPage on /pricing, Product/Offer, and FAQPage on /vs/* — still unshipped, still carried. But its blog item was a single sentence ("add BlogPosting with datePublished/dateModified — dates exist in the UI but not in JSON-LD") with no snippet, and today's crawl confirms every blog post still emits only Organization + WebSite + ImageObject JSON-LD. The blog is the asset that targets the long-tail money queries ("what is an AI employee", "AI for small business", "what does an AI job actually cost") — and AI engines citing a post can't attribute authorship or freshness without Article markup. This is the cheapest remaining citability win and it's independent of the pricing reconciliation (no prices involved).

**Where:** all 20 `/blog/*` posts (one shared component change in the blog post layout).

**Copy-paste** (emit from the post's frontmatter; dates are already rendered in the UI — verified "Last reviewed" style dates exist on /vs and post pages carry publish dates):

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "BlogPosting",
  "@id": "https://kohai.co/blog/what-is-an-ai-employee#article",
  "headline": "What is an AI teammate?",
  "description": "An AI teammate has a role, the right tools, memory and accountability. Here's what that means in practice, and how it differs from a chatbot.",
  "url": "https://kohai.co/blog/what-is-an-ai-employee",
  "image": "https://kohai.co/images/og/default.jpg",
  "datePublished": "2026-06-04",
  "dateModified": "2026-06-04",
  "author": { "@type": "Organization", "name": "Kōhai" },
  "publisher": { "@type": "Organization", "name": "Kōhai", "logo": { "@type": "ImageObject", "url": "https://kohai.co/images/og/default.jpg" } },
  "mainEntityOfPage": "https://kohai.co/blog/what-is-an-ai-employee"
}
</script>
```

(Substitute each post's real headline/description from its `<title>`/meta description — all 20 verified fetchable today. Use the post's actual publish date from the UI. If the "Last reviewed" date is newer, use it as `dateModified`.)

## Fix 1 — 🔴 CRITICAL: robots.txt is blocking the AI crawlers the GEO strategy depends on

**Severity: Critical.** This is the single biggest conflict between the site and the strategy.

`https://kohai.co/robots.txt` is serving **Cloudflare Managed content signals** that disallow every major AI crawler site-wide:

```
User-agent: GPTBot
Disallow: /

User-agent: ClaudeBot
Disallow: /

User-agent: Google-Extended
Disallow: /

User-agent: CCBot
Disallow: /

User-agent: Amazonbot
Disallow: /

User-agent: Applebot-Extended
Disallow: /

User-agent: Bytespider
Disallow: /

User-agent: meta-externalagent
Disallow: /
```

**Why this matters:** 04-content-strategy.md sets a daily GEO target — "track 10–15 AI prompts across ChatGPT/Perplexity/Claude/Gemini; log mentions" and "ensure ChatGPT/Perplexity describe Kohai as an AI colleagues/workforce platform with approval gates and open-weight models." As configured, ChatGPT (GPTBot), Claude (ClaudeBot), Google's Gemini grounding (Google-Extended), Perplexity, and Meta's AI cannot retrieve kohai.co content at all. Kohai will be invisible in the exact AI answers the strategy is built to win. Note: the Cloudflare disallow does **not** block Google/Bing search crawlers, so classic SEO is unaffected — this is purely a GEO gap.

**Fix:** In the Cloudflare dashboard, turn off the managed content-signal injection for this zone (Security → Bots, or the "Managed robots.txt" / content signals setting), then publish an explicit robots.txt that grants AI retrieval while keeping the site's own privacy posture (which is about *customer data in the product*, not about the marketing page being unreadable):

```
# robots.txt — kohai.co
User-agent: *
Allow: /

# Explicit AI-crawler allowances (GEO)
User-agent: GPTBot
Allow: /

User-agent: ClaudeBot
Allow: /

User-agent: Google-Extended
Allow: /

User-agent: CCBot
Allow: /

User-agent: PerplexityBot
Allow: /

User-agent: Amazonbot
Allow: /

User-agent: Applebot-Extended
Allow: /

Sitemap: https://kohai.co/sitemap-index.xml
```

If Gabe prefers a middle path (allow AI *answers*, decline AI *training*), the same file can split the signal per-crawler with `ai-input=yes, ai-train=no` content signals — but note Cloudflare's current managed block refuses both, so something must be overridden either way. **Decision needed from Gabe** — this is a policy choice as much as a technical one.

## Fix 2 — 🟠 HIGH: missing llms.txt and missing content-type schema (BlogPosting, Product/FAQ)

**Severity: High.** Two related gaps, one workflow.

**(a) No llms.txt.** `https://kohai.co/llms.txt` returns 404. 04-content-strategy.md explicitly lists "publish llms.txt… in week 1" as a GEO must-fix. Suggested starter (keep claims to the verified set):

```
# Kohai

> Kohai is where you hire AI colleagues — describe the outcome, and a team
> assembles, does the work in your tools, and delivers finished results.
> Open-weight models only (DeepSeek, Kimi, GLM), ~1,000 integrations connected
> on day one, approval gates for sensitive actions.

Key pages:
- [Product overview](https://kohai.co/)
- [Features](https://kohai.co/features)
- [Pricing](https://kohai.co/pricing): $29.99/mo (12,000 credits) · $99.99/mo Pro (40,000 credits, 3 seats) · $199.99/mo Max (80,000 credits, unlimited seats). 7-day free trial.
- [Technology](https://kohai.co/technology): open-weight models (DeepSeek, Kimi, GLM), no-training inference providers, per-tenant isolation
- [Comparisons](https://kohai.co/vs)
- [Blog](https://kohai.co/blog)
```

**(b) No `Article`/`BlogPosting` schema on any of the 17 blog posts.** Verified on `/blog/stop-building-ai-agents` — canonical and meta description are present, but JSON-LD is absent, so Google can't confidently attach author/date/attributes to the articles. Add per post:

```json
{
  "@context": "https://schema.org",
  "@type": "BlogPosting",
  "headline": "Stop Building AI Agents. Hire a Team Instead",
  "description": "Why your business doesn't have time to babysit agents, and what Kohai does instead.",
  "url": "https://kohai.co/blog/stop-building-ai-agents",
  "image": "https://kohai.co/images/hero/poster.jpg",
  "publisher": { "@id": "https://kohai.co/#organization" },
  "inLanguage": "en"
}
```

And on `/pricing`, add `Product` + `Offer` schema so the three tiers ($29.99 / $99.99 / $199.99, 7-day trial) are machine-readable — the price is currently only visible in prose.

**Sequencing note:** `/ai-colleagues` — the GEO anchor page named in the content strategy — is still a 404. It should be built alongside this fix and added to the sitemap + llms.txt, since it's the page designed to make AI engines describe Kohai in exactly the right words.

## Keyword-gap observation — "Hirebase" branded search demand is landing on a 302-free but silent redirect

The competitor analysis (01, §5 and vulnerability #5) flags the Hirebase brand-migration risk, and the crawl confirms it's unaddressed on-page. The May 2026 PRNewswire launch established **"Hirebase — instant AI Workforce"** in press coverage (Yahoo Finance pickup included), which created search demand for "Hirebase" / "Hirebase pricing" / "Hirebase AI." Meanwhile:

- hirebase.co 308-redirects to kohai.co — equity and traffic flow through, correctly.
- kohai.co's `Organization` schema says `alternateName: "Kohai by BasedAI"` — no mention of Hirebase.
- **No page on kohai.co contains the word "Hirebase."** The 52-URL sitemap has zero Hirebase-related content.

So buyers who read the May press coverage, search "Hirebase", and land on kohai.co meet a product that never acknowledges the name — and the unrelated hirebase.org (an AI job-search company) is competing for the same query. This is genuinely good news for Kohai, framed generously: the redirect is doing its job, and the brand query is won by default. The gap is that the default isn't claimed.

**Opportunity:** a short page — `kohai.co/hirebase` or a blog post titled something like *"Kohai was formerly Hirebase (by BasedAI) — same team, clearer name"* — would (a) capture the residual "Hirebase" branded search demand, (b) disambiguate from the unrelated hirebase.org jobs API, and (c) give AI engines a citable answer when someone asks "what happened to Hirebase AI?" Keep it factual and low-key (Japanese-brand restraint applies): state the rebrand plainly, link to the product, move on. If the /vs/ page set grows, Hirebase doesn't belong there as a competitor — it belongs here as a brand-history page.

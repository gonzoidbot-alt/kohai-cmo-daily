## Fix 1 — HIGH: Homepage and pricing titles have zero commercial keywords

**Evidence:** Homepage title is `Kōhai | Onboard AI teammates. Get work finished.` Nobody searches "onboard AI teammates" — the money keywords from 04-content-strategy.md ("AI employees for small business", "AI workforce platform", "hire AI employees") appear nowhere in the homepage `<title>`. Pricing title is just `Pricing | Kōhai` — it wastes the strongest commercial-intent URL on the site and doesn't surface the price, which is the click-magnet for this category. Meanwhile the competitors own their category terms: Lindy's pricing title/description leads with product benefit and price ("Starts at $29.99 per user per month"), Sintra's leads with "Sintra AI Pricing".

The homepage is almost certainly the strongest page on the domain; giving its title only brand + a poetic tagline burns the highest-leverage SEO asset we have.

**Copy-paste fix (homepage):**
```html
<title>Kōhai — Hire AI Teammates for Your Small Business</title>
<meta name="description" content="Hire AI teammates that finish the work — sales, content, support and ops in one AI workforce platform. Open-weight models, approval gates, free to start.">
```
(~154 chars, ≤160 limit. Keeps "colleague/teammate" register, injects both money queries: "hire AI teammates" / "AI workforce platform".)

**Copy-paste fix (pricing):**
```html
<title>Pricing | Kōhai — AI Teammate Plans from $20/mo</title>
```
The OG title/description should mirror these. Do NOT touch the visible H1 — "Onboard AI teammates. Get work finished." is the right brand line for humans; this is a metadata-only change.

## Fix 2 — HIGH: Pricing page ships no pricing schema — Lindy ships FAQPage + SoftwareApplication + Offers

**Evidence:** kohai.co/pricing renders a full FAQ (credit costs, plan differences, rollover, free-plan terms — all excellent quotable content) but its JSON-LD contains only `Organization` + `WebSite`. Lindy's pricing page ships `FAQPage` (10+ Q/As), `SoftwareApplication` with per-tier `Offer` / `UnitPriceSpecification` / `QuantitativeValue`. Two costs of the gap: (a) we lose FAQ rich results on the exact page where buyers compare cost, and (b) AI engines doing retrieval get structured, unambiguous price facts to quote — the 06-gtm playbook's entire GEO strategy (monthly 10-prompt visibility audit) depends on engines reading our pricing correctly. This was already flagged in 07-gtm-implementation-plan.md ("Month 2: pricing/alternatives page rewrite for citation — schema markup, structured proof"); it's cheap enough to pull forward.

**Copy-paste fix (add to kohai.co/pricing `<head>`; every fact below is visible on-page text, so it satisfies Google's schema-matches-content rule):**
```html
<script type="application/ld+json">
[
  {
    "@type": "FAQPage",
    "mainEntity": [
      { "@type": "Question", "name": "How much does Kōhai cost?",
        "acceptedAnswer": { "@type": "Answer", "text": "Kōhai is $20/month (8,000 credits), Kōhai Pro is $100/month (40,000 credits) and Kōhai Max is $200/month (80,000 credits). Annual pricing is $220, $1,050 and $2,100 per year. Every plan includes unlimited team seats and the whole AI team." } },
      { "@type": "Question", "name": "Is there a free plan?",
        "acceptedAnswer": { "@type": "Answer", "text": "Yes, for a limited time. Kōhai Free is $0, needs no card, is open to the first 1,000 users, and includes credits that refresh every month." } },
      { "@type": "Question", "name": "What is a Kōhai credit?",
        "acceptedAnswer": { "@type": "Answer", "text": "A credit is the unit of usage. Small tasks use 5–10 credits, medium tasks (a chart, landing page or blog post) 20–50, and large jobs (a deck, market research) 100–300. Failed tasks consume 0 credits." } },
      { "@type": "Question", "name": "Do unused credits roll over?",
        "acceptedAnswer": { "@type": "Answer", "text": "Monthly credits don't roll over; each cycle starts fresh. Add-on credits bought on paid plans never expire." } }
    ]
  },
  { "@type": "Product", "name": "Kōhai", "brand": { "@type": "Brand", "name": "Kōhai" },
    "description": "AI teammates that finish work across sales, content, support and ops, with approval gates on anything irreversible.",
    "offers": [
      { "@type": "Offer", "name": "Kōhai Free", "price": "0", "priceCurrency": "USD" },
      { "@type": "Offer", "name": "Kōhai", "price": "20", "priceCurrency": "USD" },
      { "@type": "Offer", "name": "Kōhai Pro", "price": "100", "priceCurrency": "USD" },
      { "@type": "Offer", "name": "Kōhai Max", "price": "200", "priceCurrency": "USD" }
    ] }
]
</script>
```
(Optionally mirror Lindy's richer `UnitPriceSpecification`/`billingIncrement` pattern once the basics are in. Keep the FAQ text synced with on-page copy whenever pricing copy changes.)

## Watch item (not a fix today)

robots.txt (Cloudflare-managed block) disallows `Google-Extended` and `Google-CloudVertexBot`. That blocks Gemini's grounding crawlers. Blocking training crawlers (GPTBot, ClaudeBot, CCBot…) is right and on-brand for the privacy positioning, and answer-engine crawlers we care about (OAI-SearchBot, PerplexityBot, Claude-SearchBot) are still allowed — but if the monthly AI visibility audit shows Gemini never citing kohai.co, this setting is the first suspect. Worth a deliberate decision, not a silent Cloudflare default.

## Fix #1 — Severity: CRITICAL (GEO fix of the week) — The edge is both blocking AI crawlers AND serving stale pricing to the ones that get through

**This is the Friday GEO fix. Two verified Cloudflare-layer failures, same root area, one dashboard session to fix.**

**Part A — AI-crawler block, day 3.** Fresh UA matrix today against `/` and `/pricing`: GPTBot, ClaudeBot, CCBot (and Bytespider) all return **403** ("Your request was blocked", `server: cloudflare`), while robots.txt invites everyone (`Allow: /`). OAI-SearchBot and PerplexityBot get through — so the citation surfaces partially work, but ChatGPT browsing, Claude, and Common Crawl still cannot see any kohai.co page. 09-22 documented the exact fix (Cloudflare → Security → Bots → "AI Scrapers and Crawlers" → Allow, or a WAF Skip rule for those user agents — snippet there is ready to ship); it has not been applied in the 3 days since. Every other item on this and prior drafts is invisible to those engines until this flips.

**Part B — NEW: stale cache variants are feeding wrong prices to non-browser fetchers.** Today, fetching through a plain HTTP fetcher (web_extract) returned:

- `/pricing` → the **old "Five plans" page** (retired plan structure), and
- `/vs/lindy` → a variant quoting Kohai's own tiers as **"Starter $69.99, Based $99.99, Based Max $199.99"** — a price ladder that no longer exists anywhere on the live site

while 5/5 direct browser-UA fetches return the current page ("One team. Three plans.", $19.99/$99.99/$199.99) with `cf-cache-status: HIT` and origin headers `cache-control: public, max-age=0, must-revalidate`. A HIT on a must-revalidate resource means an edge **"Cache Everything" rule is overriding origin revalidation**, and multiple variants of the same URL are cached under different cache keys (fetcher-dependent). Why this matters for GEO specifically: OAI-SearchBot and PerplexityBot *are* getting through Part A — and they may be reading the **retired $69.99 tiers** off the cached /vs/lindy variant. Wrong prices quoted by AI engines are worse than no prices: they're confident, specific, and hard to dislodge.

**Fix (no code — Cloudflare dashboard + a purge):**

1. **WAF/Bots:** Security → Bots → "AI Scrapers and Crawlers" → Allow (or WAF Skip rule per 09-22 draft § Fix #1). Unblocks GPTBot/ClaudeBot/CCBot/Bytespider.
2. **Caching:** Caching → Rules → find any "Cache Everything" / edge-TTL override on `kohai.co/*` → remove it, or set Edge TTL to "Respect origin" so `max-age=0, must-revalidate` is honored (origin is an Astro static build — it doesn't need edge-override caching to be fast).
3. **Purge:** Caching → Purge → **Purge Everything** (required: all stale variants — "Five plans" page, old /vs/* bodies — must leave the edge before crawlers re-read).
4. **Verify after** (all should print 200, and both variants should be identical):

```bash
for ua in "GPTBot/1.0 (+https://openai.com/gptbot)" "ClaudeBot/1.0 (+claudebot@anthropic.com)" "CCBot/2.0 (https://commoncrawl.org/faq/)"; do
  curl -s -o /dev/null -w "%{http_code}  $ua\n" -A "$ua" https://kohai.co/
done
# stale-variant check: run 5x, expect "One team. Three plans." every time
curl -s https://kohai.co/pricing | grep -o "Five plans\|One team. Three plans."
```

**Effort:** ~15 minutes total. **Priority rationale:** it gates every other fix (llms.txt, schema, /vs pages are all unread by the blocked engines) *and* it's actively distributing retired prices to the engines that can read the site.

## Fix #2 — Severity: HIGH — /vs/lindy misquotes Lindy's entry price, and the page's citation surface ("alternative" + FAQ) is one buried H3 with no schema

**Why this matters:** the /vs pages are Kohai's most quotable competitive asset — structured Q&A already written in ideal model-citation format — but (a) one competitor fact on the page is wrong by our own research, and (b) the content that would win "Lindy alternative" queries exists only as a single FAQ H3. 06-gtm-funnel-playbook.md: comparison pages structured as question→answer→detail are what models lift; they also have to be *accurate*, because a wrong competitor price inside an AI answer is a credibility hit Kohai can't afford while its own pricing is unstable.

**Finding A — Lindy price misquote (live /vs/lindy body, verified today).** The page states Lindy's pricing as **"Plans from about $50 to $200 a month, plus a custom plan"** (appears 3× in the at-a-glance and side-by-side blocks). Our own 01-competitor-analysis.md — sourced from lindy.ai/pricing on 2026-09-08 — documents the entry tier (**Plus**) at **$29.99/mo** with a $99.99 Pro and $199.99 Max, and notes the ladder has changed repeatedly. "From about $50" is neither our documented figure nor defensible if Lindy's page is checked. Per the 04 pillar-5 rule (factual and generous, no trash talk), a comparison that understates a competitor's entry price reads as either sloppy or slanted. **Fix:** re-verify lindy.ai/pricing the day this ships, then quote the verified ladder with a date qualifier — e.g. *"Plus $29.99/mo (3,000 credits) · Pro $99.99 (15,000) · Max $199.99 (35,000), per user, 7-day trial (lindy.ai/pricing, as of [month year])"*. Generous framing stays: Lindy's per-user ladder at $29.99 entry is genuinely cheaper per seat than Kohai's; Kohai's case is the ready-made team vs. the builder, not price.

**Finding B — "alternative" intent is invisible in structure.** On the live page, "Lindy alternative" appears exactly once, as an FAQ H3 ("Is Kohai a good Lindy alternative?") — not in the title, not in any H2. 04 lists "Lindy alternative" as a money keyword; 09-23/24 flagged the gap and it remains open. Also still absent: FAQPage JSON-LD (09-23 Fix B, open), so the three well-written Q&As are invisible to rich results and have no machine-readable question/answer pairing for AI engines.

**Fix (copy-paste):**

Add an explicit alternative-intent block as the first H2 after the intro (one paragraph, product named once, concrete difference — eligible for "Lindy alternative" queries without a new URL):

```html
<h2>Looking for a Lindy alternative?</h2>
<p>Kohai is a Lindy alternative for people who don't want to build and maintain
automations. Where Lindy gives you a visual builder for constructing your own
assistants, Kohai hands you a ready-made team of AI colleagues — describe the
outcome, and finished work (documents, decks, even deployed sites) lands in your
Library. Sensitive actions wait at an approval gate until you say go.</p>
```

Add FAQPage schema mirroring the questions already on the page (placeholder prices marked — see claim flag):

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "Is Kohai a good Lindy alternative?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Yes — Lindy is a build-it-yourself tool for creating AI assistants step by step, while Kohai gives you a ready-made team of AI colleagues that gets to work when you describe the outcome. You keep real control (per-agent permissions and approval gates) without building or maintaining workflows."
      }
    },
    {
      "@type": "Question",
      "name": "How much does Kohai cost compared to Lindy?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "[INSERT RECONCILED KOHAI LADDER — live site shows $19.99/8,000 credits; 02-positioning-icp.md says $29.99/12k; do not publish until reconciled.] Lindy's self-serve ladder is Plus $29.99, Pro $99.99, and Max $199.99 per user per month, per lindy.ai/pricing as of [month year]. Every Kohai plan unlocks the whole team rather than per-seat assistants."
```

**Effort:** H2 + schema is a template change replicated across all 11 /vs pages (each already has the Q&A copy); the Lindy price correction needs a one-time re-verification of lindy.ai/pricing and then the same correction pass on any other /vs page quoting a competitor price from memory. **Verify:** Rich Results Test on /vs/lindy; then `curl` the page post-purge to confirm the corrected body (not a cached variant) is what's served.
